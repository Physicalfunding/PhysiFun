# プロダクト方針

## サービス概要

**フィジファン（フィジカルファンディング）**

お金ではなく、スキルと時間でプロジェクトを支援するマッチングプラットフォーム。
プロジェクトリーダーが古民家再生・米作り・DIY などのプロジェクトを立ち上げ、
サポーターがスキルや時間を提供することでリターンを受け取る「フィジカルファンディング」の仕組みを実現する。

### ユーザー役割

| 役割 | 説明 |
|---|---|
| **リーダー** | プロジェクトを立ち上げ、スキル・時間の支援を募る人 |
| **サポーター** | スキルや時間でプロジェクトを応援し、リターンを受け取る人 |

> コード上の `UserType` enum では `LEADER` = リーダー、`SUPPORTER` = サポーター として扱う。

---

## チーム

| 役割 | 人数 | 担当 |
|---|---|---|
| エンジニア | 1名 | 設計・実装・インフラ |
| デザイン / 運営 | 2名 | UI デザイン・コンテンツ・審査・運営 |

**開発の基本方針:** まず自分たちが楽しめる MVP を素早く出す。完璧より速さを優先。

---

## スケール想定

- ローンチ時: 数十人規模
- 中期目標: 数百人規模
- 将来: 数千人規模（ただし「すぐではない」）

急激な成長は想定せず、段階的に対応する。

## フェーズ別リリース計画

当初は 3 フェーズ（リーダー募集 / リーダー機能 / 一般公開）で計画していたが、**リーダー募集とリーダー機能を統合した 2 フェーズ構成に変更**した。

| 新フェーズ | 旧フェーズ対応 | 内容 |
|---|---|---|
| **新 Phase 1: リーダー募集 + リーダー機能** | 旧 Phase 1 + 旧 Phase 2 | リーダーを募集し、承認後は運営がアカウント発行 → ログインしてプロジェクト編集・サポート募集準備まで行える |
| **新 Phase 2: 一般公開** | 旧 Phase 3 | サポーターが自由にアカウント登録できるようになり、プロジェクト閲覧・サポート申請が可能になる |

### Phase 移行の方法

Phase 1 → Phase 2 の移行は **ランタイムのフィーチャーフラグではなく、コード変更リリース**で行う。Phase 2 リリース PR の中で Phase 1 専用コード（`PRE_ACCOUNT` モード等）を削除し、同時に Phase 2 の新機能を追加してデプロイする。環境変数による切替は行わない。

> 旧実装では `NEXT_PUBLIC_RELEASE_PHASE` 環境変数でランタイム切替する設計だったが、ドキュメントと実装の乖離を防ぐためコード変更リリース方式に統一した。詳細は `docs-repository/docs/202604_初回リリースに向けた計画/事前クリーンアップ_旧フェーズ構造の撤回.md` 参照。

### Phase 1：リーダー募集 + リーダー機能（現在地）

**目的:** プロジェクトリーダー候補者を集めて審査し、承認後はリーダーがプロジェクトを準備できる状態まで引き上げる

**必要な機能:**

*リーダー募集の導線（非ログイン）*
- LP（ランディングページ）— リーダー募集の説明・魅力訴求
- リーダー応募フォーム（`LeaderApplication` の `PRE_ACCOUNT` モード）— 名前・連絡先・プロジェクト案などを入力して送信
- DB 保存 — 応募データを保存（運営が閲覧できる）
- 運営通知 — 応募が来たら運営に通知（メール or Slack webhook など）

*審査・アカウント発行（運営オペレーション）*
- 運営が応募内容を審査
- 承認時に運営がアカウントを発行
- 初期パスワードを応募者にメール送信
- `SUPPORTER` + `LEADER` ロールを付与

*リーダー機能（ログイン後）*
- ログイン・ログアウト
- プロジェクト作成・編集（公開ステータスは `DRAFT` / `PUBLISHED` の 2 軸、フェーズは `VISION` 〜 `COMPLETED`）
- サポート募集の作成（活動参加募集 / スキル・モノ募集）
- 募集スケジュール管理（時間帯 + 同時刻定員）
- 画像アップロード（Supabase Storage）
- マイページ（プロジェクト管理）
- LINE オープンチャット連携（事務局が作成 → リーダーに管理権限移行）

**認証:** 応募フォームは非ログイン、リーダー機能は招待制（運営がアカウント発行）

**スコープ外:**
- サポーターの自由登録
- サポーター向けの閲覧・申請機能（プロジェクト一覧ページなど一般公開導線）

---

### Phase 2：一般公開

**目的:** サポーターがプロジェクトを閲覧し、サポート募集に申請できる

**必要な機能:**

*サポーター登録・閲覧*
- アカウント自由登録（`SUPPORTER` ロール自動付与）
- プロジェクト一覧・検索・詳細ページ
- サポート募集の閲覧

*サポート申請*
- サポートチケット（1h / 2h / 4h）を指定して申請
- 同伴人数指定
- 3 ステップフロー（入力 → 確認 → 完了）
- AUTO / MANUAL 承認モードに応じた確定フロー

*サポーター向け機能*
- マイページ（参加履歴・提供時間の累計）

*リーダー応募のセルフサービス化*
- ログイン後のリーダー応募（`LeaderApplication` の `AUTHENTICATED` モード）
- Phase 1 で使っていた `PRE_ACCOUNT` モードは廃止（コードからも削除）

**認証:** サポーター自由登録、リーダー応募はログイン必須

---

> **補足**: サポーター ↔ リーダー間のメッセージングはサービス内機能としては初回リリースでは実装せず、LINE オープンチャットで代替する。「リターン」概念も使用しない。詳細は `docs-repository/docs/202604_初回リリースに向けた計画/` の各ドキュメント参照。

## 優先原則

1. **速度優先** — 完璧な設計より動くものを早く出す
2. **段階的拡張** — 次フェーズの機能を先取りしない
3. **体験品質** — SEO より UX・スピードを重視（SEO が必要なのは LP のみ）
